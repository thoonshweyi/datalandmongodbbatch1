=>Note

 This validator is combining two validation rules using $and.

validator: {
   $and: [
      { $jsonSchema: {...} },
      { $expr: {...} }
   ]
}

That means:

Document must pass the $jsonSchema
AND must pass the $expr condition
1. $jsonSchema Validation

This validates the structure and data types of the document.

$jsonSchema:{
    bsonType: "object",

The document must be an object.

Example:

{
   name: "Shirt",
   price: 1000
}
Required Fields
required: ["name","category","price","stock","createdAt"],

These fields must exist.

So this is invalid:

{
   name: "Phone"
}

because missing:

category
price
stock
createdAt
additionalProperties: true
additionalProperties: true,

Allows extra fields.

So this is valid:

{
   name: "Phone",
   category: "electronics",
   price: 500,
   stock: 10,
   createdAt: new Date(),
   brand: "Samsung"
}

because extra field brand is allowed.

If it were false, extra fields would be rejected.

2. Field Rules (properties)
name
name: {
   bsonType: "string",
   minLength: 2
}

Rules:

must be string
minimum 2 characters

Valid:

name: "TV"

Invalid:

name: 123
name: "A"
category
category: {
   bsonType: "string",
   enum: ["fashion","electronics","food"]
}

Must be one of these values only:

fashion
electronics
food

Valid:

category: "food"

Invalid:

category: "books"
price
price: {
   bsonType: ["int","long","double","decimal"],
   minimum: 0
}

Price:

must be numeric
cannot be negative

Valid:

price: 100
price: 99.99

Invalid:

price: -5
price: "100"
discountPrice
discountPrice: {
   bsonType:["int","long","double","decimal"],
   minimum:0
}

Optional field (not in required).

If provided:

must be numeric
must be >= 0
stock
stock:{
   bsonType: "int",
   minimum:0
}

Stock:

must be integer
cannot be negative

Valid:

stock: 5

Invalid:

stock: -1
stock: 5.5
createdAt
createdAt: {
   bsonType: "date"
}

Must be MongoDB Date type.

Valid:

createdAt: new Date()

Invalid:

createdAt: "2025-01-01"
3. $expr Validation

This part validates relationship between fields.

$expr:{
   $or:[
      {$eq:["$discountPrice",null]},
      {$lte:["$discountPrice","$price"]}
   ]
}

Meaning:

Either:

Condition 1
{$eq:["$discountPrice",null]}

discountPrice is null or missing.

OR

Condition 2
{$lte:["$discountPrice","$price"]}

discountPrice ≤ price

Why Use $expr?

Because $jsonSchema cannot compare two fields.

Example:

price: 1000
discountPrice: 1500

Schema types are correct,
but business logic is wrong.

So $expr prevents that.

Valid Example
{
   name: "Laptop",
   category: "electronics",
   price: 1500,
   discountPrice: 1200,
   stock: 5,
   createdAt: new Date()
}

Why valid?

all required fields exist
correct types
1200 <= 1500
Invalid Example
{
   name: "Laptop",
   category: "electronics",
   price: 1500,
   discountPrice: 2000,
   stock: 5,
   createdAt: new Date()
}

Fails because:

discountPrice > price
validationLevel
validationLevel: "strict"

MongoDB validates:

all new documents
all updated documents

Even old documents must follow rules when updated.

validationAction
validationAction: "error"

If validation fails:

MongoDB rejects operation
throws error

Alternative is:

validationAction: "warn"

which only logs warning.
